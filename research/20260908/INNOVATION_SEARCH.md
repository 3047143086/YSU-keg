# 多模态推荐查新与下一步研究假设

日期：2026-09-08。

状态：完成文献查新与实验设计；本文件不是实验结果。新候选尚未实现、未启动训练，不能宣称已有提升，也不能保证录用。本次未修改远程实验、历史失败记录或原有模型代码。

## 1. 本轮结论

不再把普通模态门控、图结构增强、局部证据重排作为默认的下一轮主线。建议先检验一个范围更小的问题：**主召回列表中的图文内容，能否帮助补充召回器在列表之外找到普通图文召回和难正例训练找不到的相关商品？**

暂称“主召回器条件化的多模态查询重写”。这是可证伪的研究假设，不是已确立的新方法。候选集合条件化、查询重写、残余召回、双头学习、交叉拟合各自均不能作为新颖性依据；完整组合也尚未被证明具有足够创新性。

本轮排除了一个看似新颖但不成立的论点：“偏好相关性”与“候选席位价值”天然构成两个不同学习问题。在普通 item Recall、固定已有集合和追加预算下，二者对未覆盖商品没有这样的本质区别，详见第 4 节。

优先级是先验证互补信号和简单方法，再决定是否实现条件查询模型。若简单对照已解释全部增益，就停止该机制，不继续堆模块维持创新叙述。

## 4. 为什么放弃“席位价值分离”作为核心创新

设用户真实评测正例为 Y，已有候选为 B，补充候选为 A，且 A 与 B 不重叠：

```text
Recall(B union A) - Recall(B) = |A intersect Y| / |Y|
```

给定 B，最大化额外命中就是在 B 外按相关性检索。若固定保留基础召回的前 b0 项，被挤出的原候选尾部也固定，其损失对补充召回器是常数。“相关但已覆盖”只需要确定性掩码，不需要学习一个网络判断是否重复。

因此，双头、遗漏样本加权或一个新命名的增益损失，没有自动超出普通相关性学习。候选内容摘要可能有实际用途，但也可能只是间接传递主模型的用户知识。还必须与直接输入主模型用户表示、经典查询反馈和相同容量的查询网络比较。

这里讨论的是观测交互下的 item Recall，不是曝光干预后的用户满意度。不得包装成因果收益估计、偏好去偏或新的理论保证。

## 5. 收窄后的可执行假设

### 5.1 研究问题

有限容量的图文召回器是否可以利用主召回器的候选内容，识别当前查询表达偏向的语义，从而改写查询，在相同排除掩码下改善尚未召回物品的排序？

例如，历史包含多个兴趣，但主模型候选主要集中在其中一个兴趣。条件查询或许能改善另一个真实兴趣的匹配。这只是示意，不是已经观察到的实验现象；增加列表语义多样性本身不等于提高 item Recall。

### 5.2 最小模型，不先堆复杂模块

复用冻结的全局图像与文本特征，物品投影与用户历史编码器保持各对照一致。不给新方法额外的原始数据、编码器或局部 token。

```text
h_u = history_encoder(training_history_u)
c_u = pool(content_of_base_candidates_u, rank_features)
q_rel = relevance_query(h_u)
q_add = conditional_query(h_u, c_u)
score_add(u, i) = dot(q_add, static_item_embedding_i)
```

图像和文本先分别使用同类轻量查询头；配额固定，不先加入用户级动态门控。物品向量可缓存，当前小目录可先精确全库打分。若之后使用 ANN，需要额外报告近似召回损失和端到端延迟。

普通相关性目标学习全部训练正例；补充查询只用严格隔离得到的遗漏正例监督。已经覆盖的正例不改标为不喜欢。未观测样本仅是标准隐反馈采样对象，不当成已知真实负例。

这套结构也可能退化为辅助正则化加难正例训练。是否值得作为方法继续研究，取决于下面的同容量对照，而不是模块名字。

### 5.3 能够否决机制的关键对照

保持实际候选 B、去重掩码、训练样本、参数量、特征和计算预算一致，只改变查询输入：

| 组别 | 条件输入 | 排除的解释 |
| --- | --- | --- |
| 无摘要 | 用户历史，等容量查询网络 | 只是更大模型或额外查询头 |
| 主模型表示 | 用户历史和主模型用户表示 | 只是蒸馏主模型的偏好知识 |
| 错配摘要 | 另一个用户的候选摘要，匹配规模和流行度分布 | 只是集合统计、物品指纹或正则化 |
| 真实摘要 | 当前用户主候选的图文摘要 | 待检验的条件查询机制 |

另加简单的候选均值查询反馈、线性加减反馈和普通遗漏正例加权。错误摘要对照必须保持真实排除集合不变，否则测到的可能只是掩码变化。真实摘要优于错配摘要只能支持模型依赖性，不能证明用户偏好的因果机制。

## 6. 实验顺序与停止条件

### 第一步：同预算互补性检查

先在 Baby 内部开发协议上比较以下候选生成方式，不训练复杂条件网络：原模型；独立图文召回加固定配额去重；分数融合；遗漏正例加权；CLEAR 风格残余学习适配。

所有方法最终恰好输出 K=200 个不同的、非历史物品。预先限制补充预算，例如 b_add 属于 {20, 50}，其余由基础召回保留。去重后按固定规则补足，不允许 200+50 对比 200。搜索深度和计算量也单独记录；相同输出数量不意味着相同检索成本。

记录新增正例、被挤出正例、净 Recall@200 增量与候选重叠。净增量按用户分别计算后平均：

```text
delta_u = (|(C_new minus C_base) intersect Y_u|
           - |(C_base minus C_new) intersect Y_u|) / |Y_u|
```

该式是指标分解，不是新的理论贡献。带真实标签挑选候选的 oracle 只作为上界诊断，绝不能混入实际推断结果。

若多个种子下连简单图文模型的净互补性都很弱，这个方向的投入优先级下降；不要直接扩展到大规模扫描。若互补性明显但只有扩大预算才出现，则不支持当前同预算主张。

### 第二步：检验条件摘要是否真的必要

在第一步最强简单对照的同一训练预算下，比较第 5.3 节四组和查询反馈对照。额外保留图像单独、文本单独、图文联合与同模态多种子集成。

完整方法若不能稳定超过“同容量图文召回 + 同样遗漏正例训练 + 同样掩码”，就否决条件查询机制。若同模态集成即可获得全部增益，则不应把它解释为图文互补。

### 第三步：确认候选增益能够传递到最终推荐

必须采用一个对所有候选都能统一打分的共同重排器，在训练内部的各路候选并集上训练，再固定其参数比较候选池。不能只给新方法一个更强排序器，基线也要经过同一排序器。

同时报告原始 BRIDGE 的端到端结果与“基础候选 + 共同重排器”的管线基线。只提高 Recall@200 而不提高最终 Recall@20/NDCG@20，不算完成用户要求。

一个容易忽略的错误：若保留原 top20，再用同一个与候选集合无关的基础分数排序，新补入的原 top200 外物品不可能挤入 top20。单纯追加候选不能在这种设定下带来最终提升。

### 数据隔离与确认标准

仅从原始训练集构造支持交互和内部监督。用于产生某个遗漏标签的目标边，必须从基础模型训练图、用户历史、共现统计和任何监督式特征训练中全部移除。官方验证与测试标签不参与遗漏标签或动作标签构造。

稀疏用户不强求提供多组正例：可以固定留出一次交互，再按用户分配训练、校准与开发角色；单交互用户保留在最终评测中，不为便利删除。各方法使用相同支持图和留出规则。

后续检查交叉拟合基础模型与完整训练基础模型的候选分布。不能只在被故意削弱的折内基础模型上证明有遗漏可补，却不验证完整模型上的增益。

Baby 先用三个固定种子筛选，通过后才确认 Sports 与第三数据域。各方法共享有限调参预算。记录配对用户差值、置信区间和种子方差；用户 bootstrap 不替代训练随机性的评估。

建议将“相对最强简单对照，Recall@20 与 NDCG@20 平均相对提高至少 2%，且种子间不出现系统性反向、Recall@10/NDCG@10 无明显退化”作为投入后续确认的工程门槛。2% 不是统计显著性的替代，也不是会议录用门槛。最终结论需要锁定配置后的独立确认，不在反复检查测试集后继续调参。
