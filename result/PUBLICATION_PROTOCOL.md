# 论文级确认实验协议

版本：2026-10-09。本文档适用于今后所有新的多模态推荐机制。它是确认实验的冻结规则，不是为某一个候选方法事后调整的报告模板。当前 `20261009_candidate_gate` 仍属于单种子验证探索，不能按本文档宣称论文结论。

## 研究范围和累计记录

- 每个新机制必须先登记一个独立假设、唯一干预、匹配对照、预注册停止条件、预算和失败判定，再开始训练。
- 使用 `result/FAILED_EXPERIMENTS.md` 作为累计失败记忆。标记为 `FREEZE` 的机制族不能换名字重复；参数扫描、改变阈值、换种子或延长预算都不能挽救已经失败的家族。
- 每次运行保留不可变的代码提交、完整配置、命令行、数据/特征/图缓存哈希、环境版本、随机数状态、最佳 checkpoint、逐用户指标、训练日志和失败包。崩溃、非有限数值和缺失臂均不能计入成功。
- 验证集用于预先登记的机制门和配置冻结；禁止根据结果挑选数据集、种子、指标、checkpoint 或子群体后再改写假设。

## 数据、划分和训练预算

确认数据集固定为 Amazon `baby`、`sports` 和 `elec` 三个域，沿用各域的 `x_label` 划分：0 为训练、1 为验证、2 为测试。所有方法使用相同的交互、物品 ID 顺序、图像/文本特征、图缓存和预处理；任何缺失或替换都必须先形成新的数据审计，不能静默替换数据集。

正式确认固定运行种子 `2026, 2027, 2028, 2029, 2030`，不选择最佳种子。每个域、每个方法使用最多 300 个 epoch、`stopping_step=20`、训练批大小 2048、评估批大小 64、四个 CPU 线程，验证 Recall@20 四位小数严格改善才保存，平局保留更早 checkpoint。方法和超参数冻结后才允许构建测试 loader。

论文主表至少包含原始 BRIDGE、候选机制和能否定该机制解释的匹配对照。对于候选负例的梯度归属假设，匹配对照为使用相同候选目标的联合更新臂；其他新机制必须在其自身协议中先冻结相应对照。同时在同一数据、特征、预算和验证选型入口上重训能取得的强基线，至少官方 MSCA，并从已登记的官方 VI-MMRec/图模型中固定一个与研究问题相关的强比较模型。缺少官方代码的重构不能替代这项要求。官方结果、历史 checkpoint、公式重构和不同特征版本只能作为明确标注的参考，不能混入“同条件独立复现”主表。

## 统计层级和确认门

主指标预先固定为 Recall@20 和 NDCG@20；同时报告 Recall@10、NDCG@10。对每个域先计算五个成对种子的候选减基线差值，再报告均值、样本标准差、每个种子的原始差值，以及 `mean(delta) +/- t(0.975, df=4) * sd(delta) / sqrt(5)` 的 seed-level 区间。用户级 paired bootstrap 先对同一用户的五种子差值取平均，再按用户成对重采样 10,000 次，固定统计随机种子 2026，取 2.5%/97.5% 分位数。验证用户 ID 和正例数必须逐项一致。这只描述用户差异，不能替代训练随机性分析；seed-level 结果和 user-level 区间必须分开命名。

确认性比较固定为三个域乘两个主指标共六项，检验对象为候选减 BRIDGE 的成对种子差值。双侧 paired t 检验使用 df=4、家族 alpha=0.05，并对六个 p 值做 Holm 校正；该小样本近似依赖差值分布假设，报告时必须明示。不能看到结果后更换检验、指标或子群体。精确双侧 sign-flip 仅作为稳健性报告：五个种子的最小 p 值为 0.0625，不得仅凭该检验声称 `p<0.05`。Recall@10/NDCG@10 的回退、活跃度分层、长尾分层和候选覆盖率作为安全性与机制证据，不在确认后改成新的主指标。

方法只有同时满足下列条件才可标为确认通过：

1. 三个域的五种子平均 Recall@20 和 NDCG@20 相对于 BRIDGE 均至少提升 0.5%，对应 seed-level 95% 区间下界为正，六项主比较通过 Holm 家族校正。0.5% 是项目的投入门槛，不是论文录用标准。
2. 候选机制在三个域的两个主指标均严格优于事先冻结的机制匹配对照；不能用对照失败来替代候选机制的正证据。
3. Recall@10、NDCG@10 相对于 BRIDGE 的五种子平均绝对差均不得低于 -0.0002，所有失败种子仍计入均值和区间。
4. 机制覆盖率、泄漏检查、输入哈希和数值守卫全部通过，且效率变化已如实报告。

任一确认门失败时，结论为 `discard` 或 `inconclusive`，不得通过增加种子、改变阈值、事后选择 checkpoint 或扩大搜索来救援同一假设。可以登记全新的、针对失败原因的假设，但必须保留原始结果和失败原因。

## 消融和归因

消融必须在冻结预算下重新训练，不能只在推理阶段关闭分支。每个新机制先冻结“移除唯一干预”和“保留计算/容量但移除所声称信号”的控制。候选负例的梯度归属假设至少包括原始 sampled BPR、候选负例 gate-only、候选负例 joint，以及 gate/behavior correction 关闭的控制。模态归因报告 `all`、`no_image`、`no_text` 和内容去除控制；`no_content` 只能称为内容去除，不能直接称为严格 ID-only，因为模型仍可能保留内容相关参数或图分支。消融默认在三个域、五个固定种子上完整报告；减少规模只能作为单独标注的探索性结果，不能补齐主确认。

严格 ID-only 必须使用独立的纯协同模型或明确关闭内容特征、内容图和内容参数的实现，并记录其代码和配置哈希。当前候选负例方案必须先从原始 base Top-K 产生集合，再仅用 TRAIN 正例过滤且不补填；将来改变候选产生方式属于另一个假设，必须独立登记，所有臂仍保持一致的预算。验证/测试标签不能参与候选负例、训练图、统计阈值或早停。

## 测试集和历史证据边界

探索阶段不得构建测试 loader，也不得在 epoch 间读取测试标签。当前 `result/DEFAULT_BASELINE.md` 已记录旧入口每 epoch 暴露测试结果、旧 checkpoint 的来源限制；这些数字只能作为工程参考，不能作为新论文方法的独立确认。

配置、方法和超参数冻结后，对每个确认模型和固定种子各进行一次最终测试评估。最终测试只输出一次完整指标和逐用户结果，不再据此选种子、checkpoint、方法或阈值。若历史运行曾读取测试集，论文中必须明确说明暴露范围，并将这些历史运行从独立确认统计中排除；重新训练不能让同一个已暴露测试划分变成“从未看过”的测试集。新实验可如实称为冻结方法后的最终评估，跨域独立证据需来自未参与开发的域或另行预先登记的外部数据。

## 效率、资源和可复现性

记录训练总时间、每 epoch 时间、有效更新步数、吞吐、峰值 GPU allocated/reserved 显存、模型参数量、图/特征缓存大小，以及 full-sort 推理 p50/p95 延迟。`nvidia-smi` 间隔采样只能标为 sampled memory，不能写成准确峰值。候选机制若依赖 dense 行为矩阵，必须先报告其内存规模并在 Electronics 上证明可运行；不得以强制 dense、缩小数据或改变图归一化绕过资源门。
